# 综合健康报告

对应 US18 的综合周报和月报。登录后在「健康报告」选择已结束的周期，可为每项指标单独指定来源。周报取结束日期及此前六天，月报取指定自然月，服务端以档案时区判定周期是否已结束。

报告保存生成时间、数据范围、七项指标统计及覆盖、实际数据来源名称、统计依据和计划完成情况。睡眠、步数、饮水、体重显示有效日均值，运动显示累计时长，饮食显示已知部分的总热量和手动、估算、未知条目数。心率显示实际采样的均值和条数。指标来源可打开同周期、同来源的时间线。计划完成情况按周期内已保存任务的安排日期统计，分母是安排数，分子是生成时仍有打卡的任务数，无任务时完成率为空。既有计划暂停或结束不会移除已保存任务。

同一用户、报告类型和日期范围内的版本从 1 递增，包括已失效的旧版本。生成与版本分配在同一事务中完成。来源冲突或无健康记录且无计划任务时返回错误。综合报告直接使用 Java 统计，无外部模型、日记正文或外部参考资料。原睡眠报告仍通过 Agent 生成，其任务链接和参考资料在报告详情显示。

睡眠报告按用户和起止日期分配版本。同一周期更换来源或日记选项后重新生成也会创建下一版。升级已有库时，在 Java 服务停止期间执行 `database/migrations/034_sleep_report_versions.sql`，按生成时间和编号为既有睡眠报告分配版本，报告编号和任务关联继续有效。

健康记录修改后，按修改前后的日期标记相关综合报告失效，跨日运动使用前后区间实际覆盖的日期。删除记录按原日期处理。撤销打卡会清除覆盖其安排日期的综合报告快照。失效清除内容及快照，保留编号、周期、生成时间和版本，按周期失效也会覆盖使用其他来源的版本。新增记录或打卡通过重新生成进入新版本。

报告列表和详情显示首次失效原因，分别为来源记录更正、来源记录删除、打卡撤销或日记及授权变更。已有库执行 `database/migrations/033_report_source_change.sql`。历史失效报告的原因未知，显示通用失效提示。

## 接口和升级

`POST /api/reports/health` 使用现有 JWT 鉴权。请求包含 `period`（`WEEK` 或 `MONTH`）和 `date`（周报结束日期或月报所在月内的任一天），可选 `sleepSource`、`stepSource`、`workoutSource`、`mealSource`、`waterSource`、`weightSource`、`heartRateSource`。成功返回 HTTP 201 和报告详情，来源冲突返回 409，无数据返回 422 `REPORT_NO_DATA`。

`GET /api/reports` 与 `GET /api/reports/{id}` 通过 `reportType` 区分 `SLEEP`、`HEALTH_WEEK`、`HEALTH_MONTH`，综合报告详情的 `statistics` 保存指标与计划快照。`reportVersion` 用于综合报告版本展示。

已有库在前序迁移后执行 `database/migrations/009_comprehensive_health_reports.sql`，新库直接使用最新的 `database/schema.sql`。沿用逻辑关联，无新增外键。
