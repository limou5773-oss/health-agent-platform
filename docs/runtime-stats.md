# 系统运行统计

对应 AD07。管理员在「管理后台 → 运行统计」选择 1 至 366 天的日期范围。起止日期均包含，按数据库现有时间字段归集。

| 指标 | 口径 |
| --- | --- |
| 任务状态 | 按任务创建日期筛选，汇总查询时的状态。完成率为完成数除以完成、失败和取消数之和。没有已结束任务时为空。 |
| 执行耗时 | 新增采样累计 Java 发起 Agent 执行请求到收到结果或失败的耗时，包含补充后的执行和手动重试轮次。按有采样的任务计算平均值。旧任务和仅套用模板的草稿没有历史采样。 |
| 首步反馈 | 从任务创建到首条 Agent 执行步骤写入的耗时，包含排队时间。仅写入一次，按已采样任务计算平均值。升级前已出现首步的历史任务和只套用模板的草稿显示暂无采样。 |
| 工具失败 | 按失败步骤写入日期和已知工具分类计数，包括睡眠明细、综合统计和打卡汇总。睡眠来源冲突计入睡眠统计工具失败，原任务仍可继续补充。仅统计已保存的步骤。 |
| 导入量 | 按批次创建日期统计睡眠、步数、体重及心率的批次、已确认批次、输入行及已入库行。无批次的已记录预览拒绝单列。已有批次的确认冲突在导入管理中查看。 |
| 计划完成 | 按任务安排日期统计当前有效任务和实际打卡，已被修订替换的任务不计入。没有有效任务时完成率为空。 |

现有「任务运行」列表同步显示累计耗时，可按任务记录核对。

点击任务状态行的「查看任务」可按已查询的周期和状态列出原任务，每页 20 条，支持打开现有脱敏审计详情。列表按打开时的状态查询，任务状态随后变化时可刷新汇总。

`GET /api/admin/runtime-stats?startDate=YYYY-MM-DD&endDate=YYYY-MM-DD` 需要管理员 JWT。已有数据库执行 `database/migrations/018_runtime_stats.sql`，新库使用最新 `database/schema.sql`。同步更新 Java、Python 和前端。

`GET /api/admin/runtime-stats/tasks` 使用同样的日期参数，另传任务 `status` 和可选的 `page`，返回编号、类型、创建时间、首步耗时和累计执行耗时。任务详情继续通过既有管理员审计接口读取。

本人任务详情同时展示两项耗时。已有数据库在适用的前序迁移后执行 `database/migrations/042_task_first_step_timing.sql`。
