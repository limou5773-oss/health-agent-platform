数据库表间使用业务编号逻辑关联，不设置外键。任务删除通过业务事务显式清理步骤、解除计划及报告关联；步骤写入与任务删除使用同一任务行锁协调。唯一约束、必要索引及事务保留。

Agent统计由Java程序计算，模型负责选择工具和解释。模型未配置或外部调用失败时返回明确错误，不生成示例健康分析。预置知识只包含标明来源的“平台睡眠统计口径”，实际医学资料由管理员自行维护。

## 当前边界

- 多源接入已有手动、通用CSV及苹果健康睡眠XML/ZIP解析代码，统一入口保留来源App、品牌、设备类型和型号。小米/红米手环、手表需整理为通用CSV；Mi Fitness原始导出包尚未适配。苹果文件尚待真实脱敏样本验证，未接入设备自动同步。跨来源时段实际重叠时要求用户明确选择，非重叠时段可以汇总。详见wearable-import.md。
- 苹果导入对同来源、同睡眠日期发生夏令时或UTC偏移切换的条目标为不支持，提示使用UTC档案时区重新导入；不会将这类条目写入正式记录或用于睡眠统计。
- 已完成的睡眠分析和综合分析可在同一数据范围内连续追问。每轮独立保存并重新查询统计，前一轮问答用于理解上下文。跨任务长期偏好由个人档案管理。
- 已生效计划可通过编辑页面或自然语言生成修订草稿，用户核对版本后单独确认。任务提醒按生效计划调度。真实模型修订待用户验收。
- 健康时间线支持按日期、类型及来源导出本人记录详情。个人档案支持导出本人已保存的各模块数据。长期偏好由用户在档案中逐项确认保存，计划草稿生成时使用最新内容。旧档案自由文本保留，偏好删除不回写历史产物。外部模型授权可按睡眠、活动、体重、心率和日记设置，日记另需逐条权限及任务勾选。普通用户可凭当前密码自助删除账号及关联数据。
- 时间线支持睡眠、步数、运动、饮食、饮水、体重、心率和日记的范围删除预览与确认。睡眠和授权日记关联的报告、分析、会话及检查点沿用已有清理流程，并清除关联任务的原请求。按范围删除健康记录时，正式计划和打卡保留。
- 计划详情支持打卡日历、到期完成率、当前和最长连续完成天数及补打卡。周期复盘使用当前有效任务和实际打卡，改期建议由用户带入修订编辑器。主动任务支持每周及每月睡眠复盘与睡眠导入后分析，默认关闭，支持站内通知和任务追溯。
- 运动管理分别维护步数及运动记录：累计取最新快照，增量区间不重叠；运动按每日实际覆盖时段合并。运动可关联已有计划项目并由用户显式打卡。当前目标可回看达标情况，未保存历史目标版本。详见activity-management.md。
- 饮食与饮水保存实际记录，Java仅按用户明确提供的份量、同单位参考热量及出处计算估算值。份量未知仍可保存，汇总标注已知热量和未知条数。饮水按实际记录相加。拍照识别提供候选和粗估份量，热量仍由用户填报或按参考值估算。详见nutrition-management.md及meal-photo.md。
- 体重管理统一使用千克，同日多次测量保留；趋势固定取每日最后测量，阶段与目标起止值可定位原始记录。目标由用户设置，未记录时不从档案或模型推断基线；记录变更后实时重算，未保存历史目标版本。现有档案体重独立保留，不增加BMI、设备同步或医学解释。详见weight-management.md。
- 日记默认不授权给Agent；任务显式includeDiary并且档案AI授权开启时，才能按需读取任务周期内最近20条当前授权日记。变更或撤销清理相关任务/草稿/步骤/检查点，并使标记允许日记的报告失效；正式计划继续保留，内部计划工具不返回正文，避免衍生文字再次流入其他任务。includeDiary表示允许使用背景，实际是否读取看工具执行步骤。外部已发送信息不能本地撤回，真实模型及撤销场景尚待用户验收。详见diary-management.md。
- 报告中心已接入七项指标的专项报告和阶段对比。苹果健康文件支持心率、体重和步数的预览与确认，真实文件待用户验收。
- US05 纠错已覆盖睡眠、步数、体重和心率。保存更正时保留来源，记录列表、时间线详情和个人数据导出体现更正标记。
- 步数导入预览显示有效记录的起止时间；活动统计和综合看板按所选日期及来源显示最后观测时间。
- 已加入计划前后对比、多目标协调、浏览器 PDF 导出、饮食照片候选、单页体检图片整理和家庭只读授权。品牌适配仍待真实样本。
- 启动脚本面向本地三进程开发；未交付生产部署、分布式任务队列或多进程检查点共享能力。

## 构建与分工

开发侧只做源码、依赖和构建检查。Java使用 `mvn -B -ntp -DskipTests package`，前端使用 `npm run build`（含TypeScript检查），Python使用 `compileall`、模块导入、图编译和依赖一致性检查。没有编写或执行自动化功能、回归或浏览器测试，也没有向真实模型发送健康数据。

功能测试与业务验收由用户执行。数据库和模型凭据填写后，按根README启动三端，再验证需求文档的对应场景；本文中的“已编写”不等同于真实业务环境已通过验收。
