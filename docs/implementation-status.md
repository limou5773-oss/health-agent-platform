数据库表间使用业务编号逻辑关联，不设置外键。任务删除通过业务事务显式清理步骤、解除计划及报告关联；步骤写入与任务删除使用同一任务行锁协调。唯一约束、必要索引及事务保留。

Agent统计由Java程序计算，模型负责选择工具和解释。模型未配置或外部调用失败时返回明确错误，不生成示例健康分析。预置知识只包含标明来源的“平台睡眠统计口径”，实际医学资料由管理员自行维护。

## 当前边界

- 多源接入目前是手动和CSV渠道，并保留记录的来源名称；不是品牌设备接入或自动同步。跨来源时段实际重叠时要求用户明确选择，非重叠时段可以汇总。
- 多轮交互目前围绕同一任务的补充信息；已完成任务后的自由连续追问、跨任务记忆管理尚未实现。
- 可以编辑待确认草稿，尚未实现已生效计划的对话修订和版本比较。
- 档案可以保存偏好，但尚未建立独立的长期记忆管理页面。授权目前控制外部模型调用，尚未做到按指标分别授权及完整账号数据一键删除。
- 修改或删除睡眠记录会清理匹配范围内的分析内容及检查点；不据此宣称已经完成全平台个人数据删除或所有派生内容的匿名化。
- 计划完成情况可按已保存任务查看；连续打卡天数、完整复盘指标、提醒和主动周期触发尚未实现。
- Apple健康XML、运动、饮食饮水、体重趋势、情绪日记、健康时间线、个人基线、综合月报及其余P1后台功能待实施。
- 拍照饮食、体检整理、计划效果分析、多目标协调、家庭空间、PDF导出、品牌适配等P2尚未实施。
- 启动脚本面向本地三进程开发；未交付生产部署、分布式任务队列或多进程检查点共享能力。

## 构建与分工

开发侧只做源码、依赖和构建检查。Java使用 `mvn -B -ntp -DskipTests package`，前端使用 `npm run build`（含TypeScript检查），Python使用 `compileall`、模块导入、图编译和依赖一致性检查。没有编写或执行自动化功能、回归或浏览器测试，也没有向真实模型发送健康数据。

功能测试与业务验收由用户执行。数据库和模型凭据填写后，按根README启动三端，再验证需求文档的对应场景；本文中的“已编写”不等同于真实业务环境已通过验收。
